How the demo works

BreachLabs runs through 7 phases, each building on the last, to produce a comprehensive security assessment.

1

Repository Intake

BreachLabs receives an authorized application repository and begins understanding its structure.

Input: Application repository path

2

Isolated Environment Setup

A disposable sandbox is created with a copy of the application, dependencies installed, and the app launched.

Action: Workspace copy, venv setup, app launch

3

Health Check & Reconnaissance

BreachLabs verifies the application is running and maps its attack surface — routes, forms, endpoints.

Output: Route list, form specs, attack surface map

4

Security Scanning

Multiple scanners run in parallel: static analysis, secret detection, and dynamic web testing.

SAST

Source code analysis

Secrets

Credential detection

DAST

Runtime testing

5

AI Investigation

The AI agent correlates findings across scanners, elevates high-confidence signals, and prioritizes what matters.

Multi-source correlation → Higher confidence → Prioritized findings

6

Verification

High-value findings are re-probed to confirm they're real. Only reproduced findings are marked as verified.

Confirmed · Inconclusive · Rejected — never overstated

7

Report Generation

An evidence-backed security report is generated with findings, evidence, verification status, and remediation guidance.

Output formats: JSON, Markdown — with full event timeline

What BreachLabs finds

The demo application contains 7 deliberate vulnerabilities. BreachLabs is designed to find and verify them.

Critical

SQL Injection

User input is directly interpolated into SQL queries without parameterization.

Vulnerable endpoint: /login

High

Reflected XSS

User input is rendered without sanitization, allowing script injection.

Vulnerable endpoint: /search

Critical

Hardcoded Credentials

Database credentials are hardcoded in source code.

Found in: app.py configuration

High

Debug Mode Enabled

Flask debug mode is enabled, exposing sensitive debugging information.

app.run(debug=True)

High

IDOR

Insecure Direct Object Reference allows accessing other users' data.

Vulnerable endpoint: /profile/

Medium

Weak Hashing (MD5)

Passwords are hashed using MD5, which is cryptographically broken.

hashlib.md5() in use

Medium

Missing Security Headers

No CSP, X-Frame-Options, or other security headers are set.

Missing: CSP, X-Frame-Options, X-Content-Type-Options

API

Programmatic access

BreachLabs exposes a REST API for triggering assessments and retrieving results. 

POST /api/assessments
Content-Type: application/json

{
  "repo_path": "/path/to/application",
  "scope": {
    "allowed_hosts": ["localhost"],
    "isolated": true
  }
}

Response:
{
  "assessment_id": "abc-123",
  "status": "in_progress",
  "created_at": "2026-09-18T10:00:00Z"
}

GET /api/assessments/{id}/report
GET /api/assessments/{id}/findings
GET /api/assessments/{id}/events
POST /api/assessments/{id}/cancel

The API runs on localhost:8000 during the demo.
