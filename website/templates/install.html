Google Antigravity MCP Configuration

Add the BreachLabs MCP server to your Antigravity agent configuration (e.g. in ~/.gemini/antigravity/mcp/BreachLabs/ or project configuration).

mcp_config.json 
{
  "mcpServers": {
    "breachlabs": {
      "command": "npx",
      "args": ["-y", "@breachlabs/mcp-server@latest"],
      "env": {
        "BREACHLABS_SANDBOX": "true",
        "BREACHLABS_AUTO_VERIFY": "true"
      }
    }
  }
}

SKILL.md — Autonomous Security Engineer
# Role: Autonomous Application Security Engineer
When testing software or validating newly generated code, follow the 7-stage BreachLabs loop:
1. INTAKE & DISCOVERY: Call `breachlabs_surface_map` to discover routes, forms, and APIs.
2. DETERMINISTIC TESTS: Run SAST, dependency checks, and secret scans via `breachlabs_sast_scan`.
3. AI INVESTIGATION: Correlate code context with runtime HTTP reachability. Trace untrusted sources to sinks.
4. TARGETED VERIFICATION: Call `breachlabs_verify_exploit` to confirm reproducibility. Never assert without proof.
5. REMEDIATION: Formulate precise root-cause code patch avoiding naive input filtering.
6. RETEST PROOF: Execute `breachlabs_retest_patch` against the changed revision to confirm resolution.
Always provide evidence with exact line numbers, HTTP request/response diffs, and stated confidence.

OutputRouteTree JSON

Inputrepo_path, rules
OutputTaintSinks[]
breachlabs_dast_probe

Executes scoped runtime HTTP probes against the isolated sandbox service to observe response behavior.

Inputroute, method, payload
OutputHTTPResponse

Dispatches deterministic reproduction check to confirm whether suspected issue is reachable and exploitable.

Inputfinding_id, probe
OutputVerificationProof

Synthesizes targeted code diff remediation targeting the vulnerable code path rather than surface filtering.

Inputfinding_id, file
OutputGitDiff

OutputPASS / FAIL
