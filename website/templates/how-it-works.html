ProductThe security loop

A security engineer inside the build loop.

BreachLabs is not a scanner with a chat interface. It is a sequence of seven stages, each producing a specific artefact, each dependent on the one before it. This page is that sequence in detail.

Deterministic measurement Agent reasoning Targeted verification Retest after change
{% with idx="01", label="Build" %}{% include "components/section-label.html" %}{% endwith %}

An application is created, modified, or handed over.

The loop starts from an artefact that exists: a repository, a running service, or both. BreachLabs records what it was given so every later claim can be traced back to a specific revision.

Input

Repository path or service endpoint, plus the environment it should run in.

Action

Validate the target, record the revision, confirm authorisation to test it.

Output

A scoped, reproducible assessment target with a fixed reference point.

{% with idx="02", label="Discover" %}{% include "components/section-label.html" %}{% endwith %}

The application tells you what it exposes.

Reconnaissance is not guesswork about hidden endpoints. It is a structured enumeration of what the running application already answers to.

Enumerated surface

discover — surface map
·HTTP routes and methods
·Form actions and accepted parameters
·API endpoints and their response shapes
·Authentication and session flows
·Static assets and client-side entry points

Why it matters

A finding without a surface is not actionable. Every later stage attaches to something on this map — which is why discovery comes before any test runs.

Boundary

Enumeration is limited to the authorised target. If the map is incomplete, the report says so rather than implying full coverage.

{% with idx="04", label="Investigate" %}{% include "components/section-label.html" %}{% endwith %}

Reasoning is written down, not implied.

The agent opens the source around each reported location, traces the data flow, and correlates it with what the running application did. The trace is part of the output.

What investigation adds

Source contextfile · line · surrounding code
Data flowwhere the value came from
Reachabilitywhich route exercised it
Related signalsthe same pattern elsewhere
Confidencestated, not assumed

What investigation does not do

It does not promote a finding to verified. Correlation raises confidence and produces context; only a targeted reproduction attempt can change the verification state.

⚠ Correlation is not proof. A pattern that looks exploitable can be unreachable in practice. BreachLabs reports it as investigating until a check says otherwise.
{% with idx="05", label="Verify" %}{% include "components/section-label.html" %}{% endwith %}

Reproduce it, or say you could not.

Verification probes are specific to the claim: parameterisation behaviour for injection, reflection for output encoding, authorisation comparison for object references.

Attempt succeeds

VERIFIED

The probe reproduced the behaviour and the evidence is attached to the finding.

{% with state="verified" %}{% include "components/status.html" %}{% endwith %}

Attempt fails

UNCONFIRMED

The claim could not be reproduced. It stays in the report with that state, rather than being dropped or overstated.

{% with idx="06", label="Fix" %}{% include "components/section-label.html" %}{% endwith %}

Remediation for this code path.

Guidance names the file, the construct to change, and the reason the change removes the condition — not just the symptom.

Example

remediation — BL-DEMO-001
·condition: untrusted value concatenated into a query
·- query = "… WHERE name = '" + term + "'"
·+ query = "… WHERE name = ?"
·+ cursor.execute(query, (term,))
·why: the value can no longer change the query's structure
{% with idx="07", label="Retest" %}{% include "components/section-label.html" %}{% endwith %}

Then prove the condition is gone.

A retest repeats the same probe against the changed application. Resolution is recorded only when the probe no longer reproduces the behaviour.

Scope

The probe is replayed for the affected surface, not the whole suite.

Comparison

Before and after behaviour are recorded side by side.

Result

Pass, fail, or still unconfirmed — with the evidence either way.
